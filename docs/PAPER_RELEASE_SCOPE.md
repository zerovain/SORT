# Paper-release scope

This release preserves the SORT optimizer and initialization. Exact paper
preprocessing and graph construction are frozen in the companion analysis
archive. The following software-layer changes do not alter that paper-specific
path:

- removal of backups, caches, dated alternatives, and development comments;
- modern package metadata and a concise README;
- a thin functional `sort.fit()` interface, plus advanced
  `SORT`/`SORTConfig`/`SORTResult` objects, that delegate to `decompose` and
  require an explicit precomputed spatial Laplacian;
- shape/orientation validation and dependency-light result export;
- an optional post-hoc conditional gene-association module;
- manuscript optimizer defaults, including the effective `lambda_neg=1.0` and
  adaptive L1 weighting used by the retained analyses;
- explicit, dataset-specific Scanpy filtering, normalization and feature
  selection in tutorials and reproduction runners rather than a SORT
  preprocessing API;
- correct global-row assembly for interleaved samples and fail-fast validation
  of missing spatial/sample fields;
- one complete simulated-atlas tutorial plus complete PDAC and embryogenesis
  atlas tutorials; paper datasets not selected as tutorials remain covered by
  the companion reproduction archive;
- redistribution of author-generated simulation data only, with biological
  inputs prepared from their original public repositories.

A deterministic CPU fixture generated by the manuscript package is included
under `tests/data/`. In the tested manuscript environment, the release matches
the reference exactly for the spatial Laplacian, `W`, `Q`, dense
reconstruction, component order, and recorded SORT parameters.

For every multi-section paper workflow, the companion analysis archive also
records and validates the observation/sample order, maps each local graph to
the corresponding global observation indices, and rejects graphs containing
cross-section off-diagonal entries. Component labels are fit-local and are not
treated as persistent identities across reruns.

Memory optimizations that alter floating-point order, backend placement,
dtype, sparse/dense execution, initializer behavior, or optimizer scheduling
are deliberately excluded. They require a separately versioned and validated
release.
